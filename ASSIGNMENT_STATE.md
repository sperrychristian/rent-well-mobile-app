# Shared state in Rent Well

The state I share across the app is the list of work orders, the repair requests a tenant reports and a landlord starts and resolves. I used React Context for it, in `store/WorkOrdersContext.js`, because it is a small list that a lot of screens in different tabs and in the drawer read and change: the landlord's Home counts, the Work Orders tab and its badge, Work Order Detail, a tenant's profile, and on the tenant side My Home, Repairs, Report an Issue, and Past Requests. Context ships with React and needs no extra setup, and Redux Toolkit would have been more setup than an app this size needs. In `App.js` the `WorkOrdersProvider` wraps the whole navigator, above the `NavigationContainer`, so every screen can reach the same orders through `useWorkOrders()`, and changing a status on Work Order Detail updates the list row, the Home subtitle, and the tab badge right away. In demo mode the orders live only in memory on the phone, and with a signed-in account a second provider inside it loads them from the Firebase Realtime Database, shows each change right away, and puts the old version back if the save fails.

Assignment 12 added a second piece of app-wide state, the signed-in session: `store/AuthContext.js` holds the Firebase token and the user record, sits above `WorkOrdersProvider` in `App.js`, and the providers below it are keyed by the user's id, so logging out or switching accounts starts every list over empty (see [ASSIGNMENT_AUTH.md](ASSIGNMENT_AUTH.md)).
