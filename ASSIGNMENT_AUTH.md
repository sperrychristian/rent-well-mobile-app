# Assignment 12: Authentication

In Rent Well every screen needs an account except Welcome, Pick a Demo Role, Log In, Landlord Sign Up, and Tenant Sign Up, and when nobody is signed in the app only registers those five screens, so a private screen can't be opened by name or by a link. Sign up and log in use the Firebase Auth REST API (accounts:signUp and accounts:signInWithPassword) through the helpers in util/auth.js, and the ID token lives in AuthContext in memory, gets saved on the phone with expo-secure-store, and is sent to the Realtime Database on every request as ?auth=. Landlords and tenants are my two kinds of users, and each Firebase account is linked to its Rent Well user record through an authLinks node keyed by the Firebase localId, so a new landlord's records are stored under their own user id and a tenant signs up with their landlord's invite code. When the app opens it reads the saved session and signs you straight back in, and since a Firebase token only lasts an hour it trades the refresh token for a new one whenever the token is about to run out, or sends you back to Log In if Firebase turns the refresh down. The database rules now only let a logged in user read or write, and logging out from Settings, either home, or the drawer clears the token from the phone and from memory.
