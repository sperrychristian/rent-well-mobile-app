# Work order form

My form is the work order form in Rent Well, and it collects a title, a description of the problem, how urgent it is (Emergency, Normal, or Low), and an optional preferred date, plus a contractor and an estimated cost when a landlord fills it in. The title has to be 3 to 60 characters after trimming, the description has to be 10 to 500 characters and shows a live counter that turns amber near the limit, and an urgency has to be picked. The estimated cost is optional, but if it's there it has to be a number from 0 to 100,000 with no more than two decimal places, and the preferred date has to be a real date in YYYY-MM-DD that isn't in the past and isn't more than a year away. Every field lives in one state object where each entry holds its value, whether it's valid, and its error message, so when I press Add with bad input each field shows its own message underneath it, a summary line shows above the buttons, and nothing gets saved. The same form also edits a work order: the pencil on a work order opens it with every field already filled in, the title changes to Edit Work Order, and the button says Update instead of Add. Valid input is saved through the shared WorkOrdersContext, so the new or changed work order shows up right away in the Work Orders list, the Home count, and the tab badge.
